rc6 优化传输：大文件优先局域网直传并校验；连接不通时自动回退 Telnet。显示大小、速度及最终校验结果。不修改防火墙规则。已完整上传的已知暂存文件继续复用，无需再次传输。

rc4 上传完成后报 sha256sum not found：用 rc5 点击“安装 / 升级”。工具核验后复用大文件，仅修复小脚本，无需先卸载。未知或不完整残留不会直接覆盖。

ZTE ONT · UU 远程开机助手 v1.0.0

支持已验证固件的 F7615MV30 与 F7005MV3，自动识别后选用各自方案。
识别不代表所有同型号固件都能安装。G7615V2 等其他型号仍未适配。

使用步骤
1. 双击 ZteOntUuWol.exe。填写目标光猫实际管理地址、用户名和密码。
   默认 192.168.1.1 / root / Zte521，可修改。如果目标管理地址为 192.168.2.1，应按实际地址填写。
   空白输入使用默认值。自动识别针对填写的地址，不自动扫描局域网或猜测其他地址。
2. 先点击“检查状态”，自动识别结果显示在设备型号及状态卡片中。识别阶段仅执行 id、uname、sha256sum。
3. 点击“安装 / 升级”，不需要手动选型号。F7005 为限定固件安装方案，不覆盖已有安装；已安装时先检查状态。
   每次操作都会重新登录识别，核对型号、aarch64 架构、固件哈希；F7005 还核对原厂启动脚本。
   不匹配时停止，不向未知设备传安装脚本，也不会改用另一型号的流程。
4. 安装期间保持连接，等待工具明确报告安装完成。
5. F7615MV30 安装完成后需要手动重启一次光猫，待网络恢复，再检查服务、自启及 UU App 在线状态，并测试远程开机。工具不会自动重启光猫。
6. F7005 安装后仍按下文分别验证 App 在线、重启自启和移动数据远程开机。

两种方案的差异
F7615MV30：沿用 v0.6.1 工具的安装逻辑及 v0.3 光猫端服务，通过 Wi-Fi 配置回调自启。
F7005MV3：沿用 0.1.0-rc1 原厂插件方案；安装器自动检测已验证的 Andlink 原始/修复版本，未知版本停止。
UU 仅 CAP_NET_RAW，固定 PID 准备程序仅 CAP_DAC_OVERRIDE。两份自有程序有 immutable 保护，以免开机 chown 清除授权；卸载先解除保护。
不改 LAN 地址，不改原厂 Java 权限规则，不承诺游戏加速。不自动重启光猫。

管理操作
- 启动服务 / 停止服务：F7615 保留原界面的独立服务操作，不改变自启；F7005 启动同时开启自启，停止同时关闭自启。
- 启用自启 / 停用自启：F7615 独立调整自启，不立即启动或停止服务；F7005 按原厂插件机制联动启动或停止。
- 卸载服务 → 保留数据：F7615 在光猫保留可恢复文件；F7005 先导出绑定到当前 Windows 用户的文档/F7005MV3-UU-WOL，再完整卸载光猫端。
- 卸载服务 → 完全卸载：按各自已有流程删除光猫端项目文件和绑定。已有电脑备份、App 设备记录不删除。
- 恢复服务：先检查状态。F7615 恢复光猫上保留的安装；F7005 弹出绑定备份选择框，再按安装流程恢复。
- 型号选项 → F7005 绑定 TGZ：仅在安装时用于恢复已有身份。只允许 .sn、.uuplugin_uuid、uu.conf 三个小文件。
- 型号选项 → 仅测试 PID 为 F7005 高级选项，默认不勾选；选中后不运行 UU，通过后在“型号选项”中点击“切换为 UU 服务”。
F7005 专用选项在 F7615 上会被拒绝，不会静默忽略。

备份与回退
各型号保留原来的备份和回退方式，不混用目录或自启入口。操作中断后先检查状态，不要重复安装。
F7005 的框架和绑定备份存于实际 Windows 用户的“文档/F7005MV3-UU-WOL”。框架备份用于恢复参考，不要直接覆盖运行中的 bundlecache。
F7005 必须使用本工具卸载，不要直接通过原厂插件页面删除，避免受保护文件无法清除。
F7615 已保留卸载的安装使用“恢复服务”。
统一版目前固定使用 Telnet 23 端口，界面保留端口显示但不可修改。
界面沿用 F7615 的布局：连接信息、操作按钮、服务管理、六张状态卡片和操作记录。

隐私与边界
工具仅连接填写的管理地址，不保存输入的密码，不自动上传设备备份或报告。
不要公开分享绑定备份、原始框架备份或设备专属报告；发行包不包含这些资料。
当前统一版未改变两种光猫的服务二进制和自启实现。已有正常运行的安装不需要重装。

F7005 完全卸载补充（v1.0.0）
完全卸载会在移除本项目插件后，清理 ConfigAdmin 中 local.ont.uuwol.f7005 和 local.ont.uuwolprobe.f7005 的 SetMsgConfig.config。插件主体已卸载时，也可以再次选择完全卸载补清理。
操作前按登记信息定位 ConfigAdmin，检查本项目插件和进程已退出、目录不是符号链接、配置 service.pid 匹配；先备份到电脑并校验，再按原 SHA-256 删除两份确切文件，仅移除其空目录。不递归删除 ConfigAdmin 缓存；检查失败或备份失败时不执行配置删除。
备份名 project-config-before-cleanup.tgz，包含原路径；仅在确需撤销本次清理时参考使用，不要直接覆盖运行中框架的缓存。电脑上的历史备份不会被完全卸载删除。
Andlink 修复及其已有备份不属于 UU 完全卸载范围，保持原样。
Java 框架自动修复见下节，限定已验证的原始版本。

F7005 自动框架修复（v1.0.0）
安装时先定位唯一 Andlink 插件缓存并核对 SHA-256。已是验证过的修复版本：跳过修改和重启，只检查 Java 进程稳定、5080 监听及原厂 andlink/cmccdpi/appcore 状态。未知版本或异常路径：停止，不安装 UU。
对于验证过的原始版本：先进行 30 秒只读健康检查，Java 进程及启动时间保持不变、5080 监听和三项原厂插件状态正常时，保留原始 JAR 直接继续安装；只有明确的运行异常才先把框架快照和原 JAR 备份到电脑，在光猫另建 /usr/plugin/ont-andlink-auto-随机标识 目录，保存原件、修复件和独立回退脚本。仅对缓存 JAR 应用校验后的 LocalIP → LocalIPv4 差分，不改 LAN、启动脚本、原厂权限规则或只读原厂 JAR。
工具等待原有故障进程自行退出后原子替换缓存，最多等待 45 秒；没有空闲窗口就停止，不强制终止正常工作的 Java 来尝试修复。修复后检查框架持续稳定 30 秒和原厂配置哈希，再继续安装 UU。
替换前设置光猫端 180 秒超时回退。连接中断或修复验收失败且未确认接受时，尝试恢复原件；回退可能终止原厂 Java 进程，由原厂管理程序重新启动，因此修复期间插件服务可能短暂中断。该保护依赖光猫持续供电，不覆盖掉电或框架本身无法恢复等故障。
电脑备份目录中有“Java框架修复回退说明.txt”，记录这次确切目录及命令：sh /usr/plugin/ont-andlink-auto-实际标识/framework-repair.sh rollback。回退前先卸载 UU；不要套用别次修复路径。不要直接把整份框架快照覆盖到运行中的缓存。
修复通过后如后续 UU 安装失败，保留已验收的框架修复和备份；UU 完全卸载不会撤销框架修复。已有的框架修复备份也继续保留。
F7615 的安装及权限流程不加载这个修复模块，不受影响。已修复自动跳过及原始版本运行正常跳过均已在参考设备验证；原始故障版本的自动修复完整流程通过本地事务模拟，尚未在另一台未修复设备实测。

框架检查异常处理：Telnet 超时、响应格式错误、检查命令异常或检查期间 JAR 改变会停止，不进入修复。原始版本健康仅代表当前网络配置下通过检查，不表示此固件在所有 LAN 设置下均无问题。

检查状态先区分未安装、已安装和不完整安装。未安装不再校验不存在的 control.sh，正常显示“未安装”；有残留、登记不一致或检查失败不会误报正常未安装。只读检查不创建电脑备份目录。

安装后验收
1. F7615 安装完成后先手动重启；F7005 也需测试重启自启。等待网络恢复后点击检查状态，再到 UU App 确认设备在线。
2. 全新安装需要绑定；保留身份恢复时确认原设备在线。选择实际用于唤醒的网卡，不要选虚拟网卡或已更换的旧网卡。
3. 手机关闭 Wi-Fi 使用移动数据，将目标电脑关机后测试远程开机。
4. F7615 首次安装后服务可能过一段时间停止，重启后已验证恢复；原因尚未定位。已有安装且重启后正常的设备无需重复重装或重启。
