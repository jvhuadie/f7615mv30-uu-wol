## 重启后日志管道实机排查补充（2026-10-25）

本次为只读排查，没有停止、重启或修改 UU，也没有向实际日志管道注入测试数据。

- 读取进程文件描述符及 fdinfo，确认 uuplugin 的 fd 1/2 均为 /dev/null。
- 按日志接收器 fd 0 的管道标识扫描持有者，确认 xuplugin-guardian 的 fd 1/2 是同一管道的写端；log-writer.sh 与其 dd 子进程持有读端。
- 日志接收器在等待子进程，dd 为休眠状态，日志大小 26 字节；UU、自启及云连接正常。
- 结论：主进程输出转向 /dev/null 不代表 guardian 也关闭了输出。当前接收器有实际写端连接，等待新数据是合理状态，无需修改现有运行方式。之前只检查主进程输出不足以解释整个管道；也不能根据进程存在或日志大小推断后续一定产生新日志。
