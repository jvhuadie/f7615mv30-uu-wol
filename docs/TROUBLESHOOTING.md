# 常见问题

## 安装后服务停止

F7615 全新安装后首次运行可能过一段时间停止，原因尚未确定。安装完成后必须手动重启光猫，待网络恢复再检查服务、自启和 App 在线。重启后已验证恢复，不代表退出问题已修复。

## 连接、安装和唤醒

| 现象 | 处理 |
|---|---|
| 登录失败 | 核对实际地址、Telnet 权限及密码；默认值不保证适合所有设备 |
| 固件不匹配或自启入口未知 | 停止操作，不绕过校验或覆盖未知文件 |
| 安装中断 | 先检查状态，保留操作记录和备份，不连续重复安装 |
| 工具版本与光猫端不同 | 正常：Windows 为 v1.0.0，F7615 服务为 v0.3，F7005 为 0.1.0-rc1 |
| 重启后 App 离线 | 先检查服务、网络和时间，不通过删除绑定掩盖故障 |
| App 在线但不能开机 | 检查目标有线网卡、主板 WOL 配置，保持电脑接电和网线连接；使用手机移动数据实际验证 |

## 日志与空间

光猫端 v0.3 对接管的标准输出／错误输出提供有界轮转：`/tmp/uu-f7615-service.log` 和 `.previous` 各最多 256 KiB，合计最多 512 KiB；位于内存盘，重启清空。自启日志 `/tmp/uu-f7615-boot.log` 每次回调覆盖。限额不覆盖闭源程序自行创建的其他文件。

若日志管道未运行，Windows 工具会再检查本项目 UU 主进程的输出去向。两者均为 `/dev/null` 时显示“当前不写入管道日志”，不直接报故障；主进程缺失或输出不明时仍提示检查。这不能单独确定日志进程退出原因。


### 日志管道运行中，但 UU 输出是 `/dev/null`，是否故障？

**这两种状态可以同时出现，不能仅凭主进程的 `/dev/null` 判断故障。** 2026-10-25 对参考 F7615MV30 重启后的实机只读排查确认：

- `uuplugin` 主进程的标准输出和错误输出均为 `/dev/null`。
- `xuplugin-guardian` 守护进程的标准输出和错误输出仍连接到日志管道的写端。
- `log-writer.sh` 及其 `dd` 子进程持有同一管道的读端，正在休眠等待新数据，并非忙循环。

当前连接关系为：`guardian 输出 → 日志管道 → log-writer / dd → /tmp 日志`；UU 主进程的输出去向与 guardian 分开。日志只有 26 字节且长期不变，只能说明本次观察期间没有新增日志，不表示接收器卡死，也不表示主进程的运行日志会被持续收集。

本次 UU 服务、自启和云连接正常，无需为了这一现象重启、重装、强行修改进程输出或关闭日志接收器。沿用现有轮转限制即可。如果服务停止、云连接断开，或出现持续增长／写入错误，再结合实际进程、管道两端和日志检查；PID 文件或主进程输出去向都不能单独作为故障依据。远程开机是否正常仍以实际唤醒测试为准。


## 卸载与回退

通过工具选择保留数据或完全卸载。F7005 不能直接从原厂插件页面删除，否则受保护文件可能残留。完全卸载不删除电脑已有备份或 App 设备记录。

框架修复的回退必须使用本次备份中的确切路径与说明，不直接覆盖运行中的插件缓存；详见[使用说明](../INSTALL.txt)。
