## 证据与安装方式

- 主机名 G7615V2、内核 aarch64；板级名称 ZTE 133 不是商品型号。
- cspd SHA256：`0afb71c8d938a82395675bc1fa96cb10ec23f5a9ab9f4f3d66073257d02c7b36`。
- ufwmg SHA256：`42b63762cec38f78bf1248245061e753d38ecbefdb5945f74356c5bff8262a40`。
- 系统 busybox、cspd、ufwmg 为 ARM32 ELF；沿用项目已有的静态 ARM64 UU 程序。内核架构和静态链接并不能替代实机运行验收。
- CU 框架 procd 所在根挂载的 lowerdir 为 `/opt/cu/framework/ufw/rootfs`，upperdir 为 `/opt/cu/apps/apps`；挂载为 rw，与宿主共用网络命名空间。嵌套应用容器不符合根挂载选择条件。
- 报告显示框架具有 `/etc/init.d`、`/etc/rc.d` 及 S95done；安装时再次检查框架唯一性、网络命名空间、procd API、ubus service 和 br0。缺项即停止。

通过宿主的 chroot 调用框架现有 rc.common/procd，在框架内创建 `/opt/uu-wol-g7615` 和 `/etc/init.d/uu-wol-g7615`，登记 S99/K10 自启链接。不使用论坛里的 SAF 密码、Telnet 回连或 USB 挂载方案，不修改原厂 rc.local、ufwmg、光猫路由或固件分区。

服务接口参考 [OpenWrt rc.common](https://github.com/openwrt/openwrt/blob/master/package/base-files/files/etc/rc.common) 和 [procd.sh](https://github.com/openwrt/openwrt/blob/master/package/system/procd/files/procd.sh)；设备实际是否支持仍由运行时检查决定。当前候选版不配置崩溃自动重启，避免尚未验证的 guardian 生命周期形成重复进程。

## 使用和验收

1. 用统一工具 v1.1.0-rc6 点击“检查状态”。仅输入你自己的光猫地址和已有 Telnet 账户；不扫描其他设备。
2. 点击“安装 / 升级”。首次安装要求没有本项目旧目录和 UU 全局运行残留。大于等于 64 KiB 的文件优先通过局域网 HTTP 直接下载，小文件走已有 Telnet；逐文件通过宿主 SHA256 校验后才使用。HTTP 连接失败会回退到较慢的 Telnet。
3. 工具先登记服务并启动，等待 5 秒确认本项目进程存在后才启用自启。启动失败则自启保持关闭，停止继续操作，保留现场诊断。进程存在不等于云端连接成功。
4. 在 UU App 中确认设备在线、绑定和移动数据远程开机，再手动重启光猫。网络恢复后重新“检查状态”，重复 App 在线和远程开机验收。工具不会自动重启。
5. “启动服务/停止服务”与自启开关独立。“保留绑定卸载”停止并取消自启，保留本项目程序和绑定，可点“恢复服务”重新启动，再按需要打开自启。“完整卸载”删除自有服务入口和项目目录。其他应用及无法确认归属的全局残留保留。

若失败，提供统一工具窗口日志即可。安装时进行针对性检查，不要求先重复运行采集器。不要反复点击安装覆盖现场；本版本拒绝覆盖已登记服务或未知残留；对 rc4 已传完但尚未登记的已知安装，点击“安装 / 升级”会逐文件核验并复用程序，仅替换小脚本。部分上传、未知文件或哈希不匹配仍停止。`START_FAILED_CHECK_LOGREAD` 表示进程启动验收失败，框架日志可通过框架内 `logread` 查看。
