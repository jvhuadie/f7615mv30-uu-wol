让中兴 **ZXHN F7615MV30 光猫**充当 UU 远程的开机辅助设备，电脑关机后仍可由常在线的光猫接收指令并发送 WOL 唤醒包。

项目面向不同型号与固件逐步扩展适配，当前可安装范围仍限于已验证的 F7615MV30 固件。其他型号需先通过只读检测、临时运行和重启验收，不能直接绕过现有安装器的固件校验。

**v0.6.1 实验版：单文件 EXE，支持安装／升级、状态检查、光猫自启开关、服务启停，以及保留数据／完全卸载两种方式。** 默认连接信息已填入，不需要复制命令或另放脚本文件。

“自启”指光猫重启后运行 UU；启用／停用自启不立即启停当前进程。点击“卸载服务”后可选择：

- **保留数据（默认）**：停止 UU、取消自启并恢复安装前入口；保留程序、绑定和备份，可点击“恢复服务”。
- **完全卸载**：停止 UU、取消自启，删除光猫上的本项目程序、绑定、日志、已识别的项目备份及本项目早期探针入口；需额外勾选确认，再次使用需重新安装并绑定。电脑备份与 UU App 云端设备记录保留。

完全卸载先核对固件、脚本、目录、备份内容、入口及进程；未知备份、符号链接、嵌套挂载或入口变化会拒绝操作。只读模式拒绝所有管理更改。

参考 F7615MV30 已完成用户侧完全卸载、重新安装和重启测试，用户反馈未发现问题。完全卸载后及重启后的实机只读检查未发现项目进程、自启入口和安装目录；详见[验证记录](VALIDATION.md)。Windows 工具为 v0.6.1，光猫端管理脚本仍为 v0.3，已安装 v0.3 无需重装。

## 开始使用

1. 下载 **`f7615mv30-uu-wol-v0.6.1.exe`**，直接双击，不需要解压。
2. 查看或修改连接信息，然后点击 **“检查状态”**。
3. 只有需要首次安装或从旧版升级时，才点击 **“安装 / 升级”**；执行期间等待操作完成后再关闭窗口。

| 连接项 | 预置值 |
|---|---|
| 光猫 IP | `192.168.1.1` |
| Telnet 用户名 | `root` |
| Telnet 密码 | `Zte521`（隐藏显示） |
| Telnet 端口 | `23` |

预置登录值不保证适用其他设备。可在窗口手动覆盖；清空 IP、用户名或密码时使用默认值。**“恢复默认”只把窗口中的连接信息恢复为上述值。** 工具不会修改光猫密码。

“检查状态”显示光猫端版本、自启、UU 云连接和日志输出情况；此操作只读，不上传或执行安装脚本，不重启 UU 或光猫。进程或云连接存在本身不代表实际远程开机成功。

## 单文件如何工作

EXE 内嵌窗口、后台、安装脚本、使用说明和公开默认配置，共九个白名单文件。启动时释放到当前用户专用的随机临时目录，逐文件校验 SHA-256 后运行；正常退出清理自己的目录，多个实例互不共享目录。强制结束进程时可能留下临时文件。

单文件版不读取旁边的 `Gui.ps1` 或 `defaults.json`。默认密码以明文配置资源内嵌，可被提取；手动输入的密码仅在进程内存中使用，不回写配置，不放入进程参数、操作记录或远程会话日志。Telnet 本身不加密，请在可信局域网使用。

运行时不启动电脑 HTTP 服务，不需要开放电脑入站端口。网易程序在光猫首次安装时下载，EXE 和源码 ZIP 都不附带其二进制。项目用途为远程开机辅助，未提供手机／电脑游戏加速适配。

## 首次安装与旧版升级

**首次安装：** 点击“安装 / 升级”，工具确认 root，通过 Telnet 上传脚本并核对 SHA-256，再执行固件、存储与入口检查，最后安装并读取状态。

**已安装 v0.2：** 点击“安装 / 升级”可原地升级至光猫端 v0.3，保留原程序、SN、UUID、`uu.conf`、自启开关和卸载恢复信息；不重新下载网易程序。升级会短暂重启 UU，不重启光猫。原脚本备份到 `backup-before-v0.3/`，新版启动失败时尝试恢复。手动修改过的未知脚本会拒绝覆盖。

**已安装 v0.3：** 只需检查状态。更换 Windows EXE 不会自动改动光猫端。

干净安装后，在 **UU 主机加速器 → 路由器加速 → 合作款路由器** 中发现并添加设备（可能显示 OpenWrt），再在电脑 **UU 远程 → 远程开机配置／开始协助** 中关联辅助设备并配置 WOL，手机与电脑使用同一 UU 账号。客户端名称与入口可能随版本变化。

已有本项目安装时优先保留本机绑定。**不要通过删除原设备并重新添加来掩盖重启后绑定丢失。** 本机工作备份的恢复路径见[完整说明](F7615-INSTALL-v0.6.1.txt)。

1. 光猫正常重启，等待联网恢复后再等约一分钟，不手动启动 UU。

4. 手机关闭 Wi-Fi，使用移动数据在 UU 远程中开机，确认电脑实际启动。

## 日志与空间

光猫端 v0.3 对接管的标准输出／错误输出提供有界轮转：`/tmp/uu-f7615-service.log` 和 `.previous` 各最多 256 KiB，合计最多 512 KiB；位于内存盘，重启清空。自启日志 `/tmp/uu-f7615-boot.log` 每次回调覆盖。限额不覆盖闭源程序自行创建的其他文件。

若日志管道未运行，Windows 工具会再检查本项目 UU 主进程的输出去向。两者均为 `/dev/null` 时显示“当前不写入管道日志”，不直接报故障；主进程缺失或输出不明时仍提示检查。这不能单独确定日志进程退出原因。


### 日志管道运行中，但 UU 输出是 `/dev/null`，是否故障？

**这两种状态可以同时出现，不能仅凭主进程的 `/dev/null` 判断故障。** 2026-10-25 对参考 F7615MV30 重启后的实机只读排查确认：

- `uuplugin` 主进程的标准输出和错误输出均为 `/dev/null`。
- `xuplugin-guardian` 守护进程的标准输出和错误输出仍连接到日志管道的写端。
- `log-writer.sh` 及其 `dd` 子进程持有同一管道的读端，正在休眠等待新数据，并非忙循环。

当前连接关系为：`guardian 输出 → 日志管道 → log-writer / dd → /tmp 日志`；UU 主进程的输出去向与 guardian 分开。日志只有 26 字节且长期不变，只能说明本次观察期间没有新增日志，不表示接收器卡死，也不表示主进程的运行日志会被持续收集。

本次 UU 服务、自启和云连接正常，无需为了这一现象重启、重装、强行修改进程输出或关闭日志接收器。沿用现有轮转限制即可。如果服务停止、云连接断开，或出现持续增长／写入错误，再结合实际进程、管道两端和日志检查；PID 文件或主进程输出去向都不能单独作为故障依据。远程开机是否正常仍以实际唤醒测试为准。

## 排查与管理

| 现象 | 处理 |
|---|---|
| 登录失败 | 核对光猫 IP、端口、Telnet 状态和实际密码；工具不反复尝试登录 |
| 固件指纹不同 | 停止安装，不绕过检查 |
| 安装中连接中断 | 安装结果可能未知，先检查状态，再决定下一步 |
| 提示未知自启脚本 | 保留原入口，不强行覆盖 |
| 重启后设备离线 | 检查状态与日志，先不要重新绑定 |
| 插件在线但电脑不启动 | 检查电源、有线连接、主板及网卡 WOL 配置 |

Telnet 管理命令为 `sh /usr/plugin/uu-wol-f7615/control.sh <操作>`：`status` 查看状态，`log` 查看日志，`stop`／`start` 启停，`disable`／`enable` 停用或启用后续自启，`uninstall` 恢复安装前入口并保留私有文件。停用自启不停止当前进程；需要完全停止时先 `disable` 再 `stop`。

源码 ZIP 附带 `Console.cmd`、`Check-console.cmd` 和 `Manual.cmd` 备用入口。`Manual.cmd` 是旧三条命令的局域网 HTTP 传送方式；其他认证提示符不受自动登录支持时可使用。GitHub 自动生成的 `Source code` 归档没有预编译 EXE，直接运行优先下载本页单文件附件。

**请勿公开光猫安装目录、SN、UUID、`uu.conf`、工作备份或固件导出包。** 此仓库及 Release 不包含用户绑定、密码输入记录或私有备份。
